# Обновление интерфейса MISIS Space

Проверена опубликованная страница https://nikitauskov.github.io/MISIS-Space/: экран до входа и форма входа/регистрации на компьютере. Проверен локальный исходный код мобильной версии. Наблюдение пользователя о недоступности входа с телефона подтвердилось в CSS: мобильное правило скрывало topbar целиком.

## Исправления

- Вход и регистрация доступны в верхней панели на телефоне и компьютере. После входа показана почта текущего аккаунта.
- До входа отображается предложение войти или зарегистрироваться. Расписание и счётчики не выдают незагруженные данные за отсутствие броней или свободное помещение.
- При первой загрузке показано состояние ожидания, при ошибке — кнопка повторной загрузки. Если обновление уже загруженных броней не удалось, виден текст о ранее полученных данных. Перед открытием новой формы после ошибки требуется обновление.
- Карточки помещений и счётчики следуют выбранному дню. Надпись «Пока свободно» заменена на точное «Броней на этот день нет».
- Пустой результат фильтра/поиска отделён от отсутствия броней. Есть сброс фильтров. Поиск сбрасывается после создания бронирования, чтобы новая запись была видна.
- На телефоне во всех четырёх видах календаря оставлена одна белая кнопка «Добавить бронирование». Синяя нижняя кнопка убрана. Названия действий приведены к одному варианту.
- Проверка доступности соблюдает те же ограничения времени и даты, что сохранение: 08:00–22:00 с шагом 15 минут.
- При просмотре чужой брони объясняется, почему нельзя изменить или удалить её. Даты месяца открываются через настоящие кнопки, доступные с клавиатуры.
- Улучшен контраст второстепенных подписей и видимость фокуса. Увеличены основные кнопки навигации на телефоне. Кнопки входа и регистрации показывают состояние отправки.
- Сохранены регистрация без писем, общая база и ограничения редактирования по автору. Обновляемые ресурсы получили версию в адресе, чтобы браузер не использовал старые стили/скрипты.

## Как обновить GitHub Pages

1. Распакуйте архив.
2. В репозитории MISIS-Space откройте существующую папку docs.
3. Add file → Upload files: загрузите ЧЕТЫРЕ ФАЙЛА ИЗ docs архива: index.html, styles.css, app.js, api.js. Не перетаскивайте папку целиком, чтобы не создать docs/docs.
4. Commit changes. Дождитесь успешного pages build and deployment в Actions.
5. Откройте опубликованный сайт. На компьютере обновите страницу Ctrl+F5, на телефоне откройте заново.

config.js не входит в обновление: ваши Project URL и publishable key сохраняются. SQL повторно запускать не нужно. Настройки Supabase оставьте: Allow new users to sign up включён, Email включён, Confirm email выключен, анонимный вход выключен.

## Проверки и пределы проверки

71 автоматическая проверка прошла: 26 хранилища, 12 формы/календаря, 12 регистрации и 21 состояния интерфейса/DOM/CSS. Для верхней панели проверен применимый каскад CSS на ширинах 320, 390, 768, 900, 1024 и 1440 px. Ответы сервера имитируются; тесты не создавали аккаунты или брони в рабочей базе.

Это не измерение реальной геометрии, переноса строк или экранной клавиатуры смартфона. В текущей среде установка браузера для локального визуального прогона завершилась ошибкой загрузки. Поэтому визуальная проверка исправленной версии на физических устройствах остаётся необходимой после публикации. Обновлённые файлы подготовлены; рабочий сайт автоматически не заменялся.

После публикации проверьте с телефона: видны «Войти» и «Регистрация»; новый аккаунт входит без письма; белая кнопка открывает форму; существующие брони видны; чужая бронь не редактируется. На компьютере выберите другой день и убедитесь, что карточки помещений показывают его дату.
