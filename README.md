# МИСИС — бронирование помещений

Одностраничное приложение по предоставленному HTML: исходная палитра и структура сохранены. Сайт предназначен для GitHub Pages и не требует сборки.

**Начните с [инструкции по запуску](DEPLOY.md).** Для общего расписания нужно один раз подключить Supabase. Без этого брони сохраняются только в текущем браузере, что явно указано на экране.

## Возможности

- Календарь: неделя, день, месяц и список; переход по датам, поиск и фильтры помещений.
- На экранах до 900 px — компактное расписание выбранного дня, выбор дней недели и полноэкранная форма.
- Бронирование 4 зала, переговорной и чилл-зоны 3 зала, всего 3 зала.
- Встречи в переговорной и чилл-зоне могут идти одновременно. Бронь всего 3 зала занимает обе зоны.
- Интервалы 08:00–22:00 с шагом 15 минут. Окончание одной встречи может совпадать с началом следующей.
- Время и текущая дата — московские независимо от часового пояса устройства.
- В общем режиме — вход по почте и паролю; все вошедшие участники видят расписание, изменять и удалять можно свои брони.
- База запрещает пересечения при одновременной отправке с разных устройств. Устаревшая правка не перезаписывает более новую.
- Расписание обновляется раз в 15 секунд при открытой вкладке, при возвращении во вкладку и по кнопке «Обновить».
- При ошибке сохранения форма остаётся открытой, сообщение об успешной записи не показывается.

## Файлы

| Путь | Назначение |
| --- | --- |
| `docs/index.html` | Страница приложения |
| `docs/styles.css` | Десктопное и мобильное оформление |
| `docs/app.js` | Календарь, форма, поиск, управление бронями |
| `docs/api.js` | Локальное хранение и подключение общей базы |
| `docs/config.js` | URL Supabase и публичный ключ |
| `supabase/schema.sql` | Таблица, ограничения, права доступа |
| `DEPLOY.md` | Пошаговая публикация через сайт GitHub |
| `TEST_REPORT.md` | Что проверено и что ещё требует проверки |
| `tests/` | Проверки логики и браузерный тест |
| `.github/workflows/check.yml` | Автоматическая проверка в GitHub Actions |

В файлах нет действующих ключей, паролей или персональных данных из старых бронирований. Начальный календарь пустой. Записи исходного HTML не переносятся в рабочую базу автоматически.

## Локальное открытие

Можно открыть `docs/index.html` двойным щелчком. Если браузер запрещает хранение при открытии файла, используйте локальный сервер. Из папки проекта в Windows:

```powershell
py -3.11 -m http.server 8765 --directory docs
```

Откройте `http://localhost:8765/`. На телефоне используйте опубликованный HTTPS-адрес GitHub Pages.

## Проверки для разработчика

Для проверки логики нужен Node.js 22:

```powershell
npm test
```

Для браузерного теста:

```powershell
npm install
npx playwright install chromium
npm run test:browser
```

Браузерный тест запускает собственный локальный сервер. Он проверяет операции с бронями и отсутствие горизонтального переполнения на ширинах 320, 360, 390, 430, 768, 900, 1024, 1440 и 1920 px во всех четырёх режимах. Для скриншотов в PowerShell:

```powershell
$env:SCREENSHOTS="1"
npm run test:browser
```

Скриншоты появятся в `screenshots/`. Эти проверки не подключают реальный Supabase. Его нужно проверить по шагам в инструкции после настройки.

## Границы текущей версии

Нет самостоятельной регистрации, восстановления пароля через сайт и административного интерфейса. Учётные записи и административные изменения организатор выполняет в Supabase. Вход сохраняется в текущей вкладке и переживает её обновление; после закрытия вкладки может потребоваться повторный вход. Работа с общей базой требует интернета. Локальные брони не синхронизируются и не импортируются в общую базу.

Публикация не выполнена от вашего имени: подготовлен комплект для загрузки в ваш репозиторий.
